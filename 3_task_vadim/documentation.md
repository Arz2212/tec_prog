# 1 Введение

Программный комплекс «Система управления складом» (Warehouse Management System, WMS) предназначен для автоматизации учёта и контроля движения металлопрофиля на складском терминале. Система позволяет регистрировать паллеты с профилем, отслеживать их перемещение в складском пространстве, фиксировать действия работников (пополнение запаса, отбор, перенос между паллетами), а также контролировать доставку профиля к обрабатывающим станкам.

## Функциональные возможности

- Управление паллетами: создание новой паллеты с указанием артикула профиля, наименования и начального количества; удаление пустой паллеты; изменение координат паллеты в пространстве склада.
- Учёт профиля: пополнение запаса профиля на паллете (оператор +=); отбор профиля с паллеты (оператор -=) с контролем неотрицательности остатка.
- Перемещение между паллетами: перенос заданного количества профиля с одной паллеты на другую с автоматической записью в журнал операций.
- Доставка к станку: списание профиля с паллеты и регистрация поступления на обрабатывающий станок; проверка существования станка с выдачей детализированной ошибки через механизм get_last_error.
- Моделирование системы компьютерного зрения: хранение результатов распознавания профиля на изображениях (класс locim) и в трёхмерном пространстве (класс loctr), а также генерация событий камер (полиморфная иерархия Event).
- Журналирование: автоматическая запись всех действий работников и станков в хронологическом порядке с временными метками.
- Диагностика: встроенные C++-тесты (run_cpp_tests) и Python-тесты (run_tests), проверяющие корректность бизнес-логики и обработку ошибочных ситуаций.
- Консольный интерфейс: интерактивное меню на Python, позволяющее выполнять все операции в диалоговом режиме.

## Технологический стек

- Язык C++ (стандарт C++17) — реализация бизнес-логики, объектно-ориентированная модель предметной области.
- Python 3.14 — консольный пользовательский интерфейс и тестовые сценарии.
- pybind11 — библиотека для создания Python-привязок к C++-коду; обеспечивает бесшовное взаимодействие между языками.
- Компилятор MSVC — сборка C++-модуля в динамическую библиотеку (warehouse_cpp).
- LaTeX — подготовка технической документации.

# 2 Архитектура проекта

## 2.1 Общая схема

Проект построен по двухуровневой архитектуре «ядро — интерфейс»:

1. Ядро на C++ — реализует предметную область (классы palete, cam, worker, machine, warehouse), бизнес-логику складских операций, иерархию событий системы видеонаблюдения, а также самодиагностику (run_cpp_tests).

2. Интерфейс на Python — скомпилированный C++-модуль (warehouse_cpp) импортируется в Python-скрипты, после чего с классами и функциями C++ можно работать как с обычными объектами Python. Над этим слоем построен консольный UI (warehouse_ui.py) и набор тестов (test_warehouse.py).

Схема взаимодействия компонентов:

```
+----------------------------------+     pybind11     +----------------------------------+
| Python UI / Tests                | <--------------> | C++ Core Library                 |
| (warehouse_ui.py,                |                  | (warehouse_lib_v4.1.cpp)         |
|  test_warehouse.py)              |                  |                                  |
+----------------------------------+                  +----------------------------------+
        |                                                    |
        | ввод/вывод                                         | складские сущности,
        | (stdin/stdout)                                     | бизнес-логика,
        v                                                    | журнал операций
+----------------------------------+                         |
| Консоль (терминал)               |                         v
| пользователя                     |                  +----------------------------------+
+----------------------------------+                  | std::vector контейнеры           |
                                                      | (паллеты, камеры,                |
                                                      |  работники, станки,              |
                                                      |  записи, события)                |
                                                      +----------------------------------+
```

## 2.2 Состав проекта

Ключевые файлы проекта:

- **warehouse_lib_v4.1.cpp** — основной C++-файл, содержащий все классы предметной области, тесты (run_cpp_tests) и объявление pybind11-модуля warehouse_cpp. Единственный исходный файл C++-части (single translation unit).

- **warehouse_ui.py** — консольный интерфейс с циклическим меню; каждая операция реализована отдельной функцией (ui_*).

- **warehouse_ui_v4.1.py** — расширенная версия UI с улучшенной обработкой ошибок (использует warehouse.get_last_error() для вывода диагностических сообщений).

- **test_warehouse.py** — интеграционные тесты: запуск C++-тестов и эмуляция полного сценария работы склада.

- **test_warehouse_v4.1.py** — расширенный набор тестов, включающий проверку обработки ошибки при доставке к несуществующему станку (test_deliver_to_missing_machine).

- **команды для запуска** — текстовый файл с командной строкой сборки C++-модуля.

## 2.3 Взаимодействие C++ и Python

Связь между языками реализована через библиотеку pybind11. Внутри C++-кода объявлен pybind11-модуль с именем warehouse_cpp:

- Классы palete, worker, machine экспортируются с их конструкторами, полями и методами.
- Класс warehouse экспортируется с методами для всех складских операций; лямбда-функция используется для вывода состояния (print_state).
- Глобальная функция run_cpp_tests() экспортируется для запуска встроенных C++-тестов из Python.

Python-скрипты импортируют модуль стандартным образом:

```python
import warehouse_cpp as wc

# Создание объектов C++ из Python
p = wc.Palete()
p.set_article(1001)
p.pfl_name = "Profile A"
p.amt_pf = 10
w = wc.Warehouse()
w.add_pallet(p)
w.add_worker(wc.Worker(1, "Alice"))
```

Благодаря pybind11 все обращения к C++-методам происходят нативно, без промежуточного сериализатора, что обеспечивает высокую производительность операций.

- Компилятор: Microsoft Visual C++ (MSVC), входящий в состав Visual Studio 2022 (или Visual Studio Build Tools).

```txt
pip install pybind11
```

- Заголовочные файлы Python и библиотека python314.lib.

## 3.2 Сборка C++-модуля

В проекте не используется CMake или Makefile — сборка производится непосредственным вызовом компилятора MSVC с формированием динамической библиотеки (.pyd).

```txt
cl /EHsc /std:c++17 /LD warehouse_lib_v4.1.cpp ^
/I"C:\Users\night\AppData\Local\Python\pythonore-3.14-64\Include" ^
/I"C:\Users\night\AppData\Local\Python\pythonore-3.14-64\Lib\site-packages\pybind11\include" ^
/link /LIBPATH:"C:\Users\night\AppData\Local\Python\pythonore-3.14-64\libs" ^
python314.lib /OUT:warehouse_cpp.pyd
```

Пояснение флагов:
- /EHsc — включение поддержки исключений C++ (необходимо для pybind11).
- /std:c++17 — явное указание стандарта C++17.
- /LD — создание DLL.
- /I ... — пути к заголовочным файлам Python и pybind11.
- /link /LIBPATH:... — путь к библиотечным файлам Python.
- python314.lib — импортная библиотека Python 3.14.
- /OUT:warehouse_cpp.pyd — имя выходного файла (.pyd для Python-расширения).

## 3.3 Запуск Python-скриптов

# 4 Документация C++

Все классы и функции C++ реализованы в одном файле warehouse_lib_v4.1.cpp.

## 4.1 Класс palete (паллета)

Моделирует паллету с металлопрофилем на складе. Характеризуется координатами (для системы видеонаблюдения), артикулом профиля, его количеством и наименованием.

### Поля данных
- `double x1, x2, x3, x4` (private) — координаты паллеты в пространстве склада.
- `long article` (private) — артикул профиля.
- `int amt_pf` (public) — текущее количество единиц профиля.
- `int last_amt_pf` (public) — количество после предыдущей смены (для анализа динамики).
- `std::string pfl_name` (public) — наименование профиля.
- `long last_article` (public) — артикул в предыдущую смену.

### Конструкторы
- `palete()` — по умолчанию (все поля обнуляются).
- `palete(double _x1, double _x2, double _x3, double _x4, const std::string& name, long art, int amt, int last_amt = 0, long last_art = 0)` — параметризованный.

### Методы доступа
- `void set_coords(double _x1, ..., double _x4)` — установка координат.
- `void get_coords(double& _x1, ..., double& _x4) const` — чтение координат.
- `long get_article() const` — получение артикула.
- `void set_article(long art)` — установка артикула.
- `bool is_empty() const` — проверка, пуста ли паллета (amt_pf == 0).
- `void print(std::ostream& os) const` — вывод в поток.

### Операторы
```cpp
palete& operator+=(int a);  // Пополнение паллеты (игнорирует отрицательные)
palete& operator-=(int a);  // Отбор (списывает всё имеющееся при превышении, предупреждает в cerr)
```

Оба возвращают ссылку на объект для цепочечных вызовов.

## 4.2 Класс cam (камера)

Моделирует камеру видеонаблюдения на складе.

### Поля
- `double x1, x2, x3, x4` (private) — положение и ориентация.
- `double phi` (private) — горизонтальный угол обзора.
- `double framesize` (private) — размер кадра.

### Методы
- `void set_position(...)` / `get_position(...)` — установка / чтение координат.
- `double get_phi() const`, `double get_framesize() const` — чтение параметров.
- `void print(std::ostream& os) const` — вывод в поток.

## 4.3 Классы worker и recordsw

**worker** — базовый класс работника склада.
- Поля: `id` (табельный номер), `name` (имя).

**recordsw** — запись о движении профиля, выполненном работником. Наследует worker (публично).
- Дополнительные поля:
  - `int timest` — время начала операции.
  - `int timeend` — время окончания операции.
  - `int amm` — количество перемещённого профиля.
  - `long art` — артикул.
- Методы доступа: `get_start_time()`, `get_end_time()`, `get_amount()`, `get_article()`.

## 4.4 Классы machine и recordsm

**machine** — обрабатывающий станок.
- Поля: `id`, `name`.
- Методы: `get_id()`, `get_name()`, `print()`.

**recordsm** — запись о доставке профиля на станок. Наследует machine (защищённо).
- Хранит те же временные метки, количество и артикул, что и recordsw.

## 4.5 Структуры и классы для системы позиционирования

### Point2D и Point3D
```cpp
struct Point2D { int x; int y; };
struct Point3D { double x; double y; double z; };
```

### locim (локализация на изображении)
- `int cam_id` — идентификатор камеры.
- `std::vector<Point2D> points` — 2D-точки профиля на изображении.
- `void add_point(int x, int y)` — добавить точку.
- `void clear()` — очистить набор точек.

### loctr (трёхмерный трек профиля)
- `long article` — артикул отслеживаемого профиля.
- `std::vector<Point3D> points` — массив точек трека.
- `void add_point(double x, double y, double z)` — добавить точку.
- `long get_article() const` — получить артикул.
- `const std::vector<Point3D>& get_points() const` — получить точки трека.

## 4.6 Иерархия событий Event

Базовый абстрактный класс Event:
- `int cam_id` — идентификатор камеры.
- `int x, y` — координаты события на изображении.
- `virtual void show(std::ostream& os) const = 0` — чисто виртуальный метод.
- `virtual ~Event()` — виртуальный деструктор.

Производные классы:
- **WorkerPickupEvent** — работник взял профиль (+worker_id, article).
- **WorkerAppearEvent** — работник с профилем появился в кадре (+worker_id, article).
- **DeliveryToMachineEvent** — профиль доставлен к станку (+machine_id, article).

Контейнер `std::vector<Event*>` позволяет единообразно обрабатывать события разных типов через виртуальный вызов show().

## 4.7 Класс warehouse (склад)

Центральный класс, объединяющий все сущности и реализующий бизнес-логику.

### Приватные векторы
- `std::vector<palete> pallets` — все паллеты.
- `std::vector<cam> cameras` — камеры.
- `std::vector<worker> workers` — работники.
- `std::vector<machine> machines` — станки.
- `std::vector<recordsw> worker_records` — журнал действий работников.
- `std::vector<recordsm> machine_records` — журнал доставок на станки.
- `std::vector<locim> image_positions` — результаты распознавания на изображениях.
- `std::vector<loctr> track_positions` — трёхмерные треки.
- `std::string last_error` — текст последней ошибки.

### Вспомогательные (private) методы
- `int find_pallet_by_article(long article) const` — поиск паллеты по артикулу; возвращает индекс или -1.
- `int find_machine_by_id(long id) const` — поиск станка по идентификатору.
- `void set_error(const std::string& msg)` — запись ошибки и вывод в std::cerr.

### Публичные методы — управление объектами
- `void add_camera(const cam& c)`
- `void add_worker(const worker& w)`
- `void add_machine(const machine& m)`
- `void add_pallet(const palete& p)` — добавляет паллету; предупреждение при дубликате артикула.
- `void create_empty_pallet(...)` — создаёт пустую паллету.
- `bool remove_pallet(long article)` — удаляет паллету (только пустую).

### Публичные методы — операции с профилем
- `bool add_profile_to_pallet(long article, int amount, long worker_id, int t_start, int t_end)` — пополнение. Создаёт запись в worker_records.
- `bool take_profile_from_pallet(long article, int amount, long worker_id, int t_start, int t_end)` — отбор. При превышении списывает всё имеющееся.
- `bool move_profile_between_pallets(long from_article, long to_article, int amount, long worker_id, int t_start, int t_end)` — перемещение с откатом при ошибке.
- `bool move_pallet(long article, double x1,...,double x4, long worker_id, int t_start, int t_end)` — изменение координат.
- `bool deliver_to_machine(long article, int amount, long machine_id, int t_start, int t_end)` — доставка к станку. Проверка существования станка; запись ошибки через set_error.
- `int get_pallet_amount(long article) const` — количество профиля на паллете (-1 если не найдена).

### Публичные методы — позиционирование
- `void add_image_location(const locim& li)` — регистрация результата распознавания.
- `void add_track_location(const loctr& lt)` — регистрация 3D-трека.
- `void check_visibility() const` — проверка согласованности.

### Прочие методы
- `std::string get_last_error() const` — текст последней ошибки.
- `void print_state(std::ostream& os) const` — вывод состояния склада.

## 4.8 Встроенные C++-тесты (run_cpp_tests)

Функция `bool run_cpp_tests()` запускает серию проверок:

1. **Тест операторов palete**: создание паллеты с 10, +5 (должно стать 15), -3 (должно стать 12).
2. **Тест складских операций**: создание склада с двумя паллетами, пополнение первой на 10, перемещение 4 единиц со второй на первую. Проверка остатков: 6 и 4.
3. **Тест обработки ошибок**: попытка пополнения несуществующей паллеты — ожидается false.
4. **Тест доставки к станку**: паллета с 20 единицами, доставка 5 к станку — остаток 15.
5. **Тест полиморфизма событий**: контейнер `vector<Event*>` с тремя событиями разных типов, вывод через show(), корректное удаление через виртуальный деструктор.

Возвращает true, если все тесты пройдены (счётчик ошибок == 0).

## 4.9 PYBIND11-привязки

Модуль warehouse_cpp определяется макросом `PYBIND11_MODULE`. Для каждого класса создаётся pybind11-обёртка:
- Для palete: вспомогательная функция `palete_to_string` привязана через `.def("__str__", ...)` для поддержки `str(p)` в Python.
- Метод `print_state` обёрнут в лямбда-функцию, передающую `std::cout`.
- `run_cpp_tests` экспортируется напрямую как функция модуля.

# 5 Документация Python

## 5.1 Модуль warehouse_cpp

Скомпилированный C++-модуль (warehouse_cpp.pyd) импортируется стандартным оператором import.

### Класс Palete
- `Palete()` — конструктор.
- `get_article() -> int`
- `set_article(art: int)`
- `amt_pf: int` — свойство.
- `pfl_name: str` — свойство.
- `__str__() -> str`

### Класс Worker
- `Worker(id: int = 0, name: str = "")`
- `id: int` — свойство.
- `name: str` — свойство.

### Класс Machine
- `Machine(id: int = 0, name: str = "")`
- `get_id() -> int`
- `get_name() -> str`

### Класс Warehouse
- `Warehouse()` — конструктор.
- `add_pallet(p: Palete)`
- `add_worker(w: Worker)`
- `add_machine(m: Machine)`
- `add_profile_to_pallet(article, amount, worker_id, t_start, t_end) -> bool`

# 6 Заключение

Разработана система управления складом на C++ с пользовательским интерфейсом на Python, взаимодействующих через pybind11. Система реализует полный цикл учёта металлопрофиля: регистрацию паллет, пополнение запаса, перемещение между паллетами и доставку к обрабатывающим станкам, с обязательным журналированием всех операций.

Ключевые особенности:
- ООП на C++ с наследованием (recordsw от worker, recordsm от machine), полиморфизмом (иерархия Event) и перегрузкой операторов (+=, -=).
- Разделение ответственности: C++-ядро — бизнес-логика и данные; Python-интерфейс — взаимодействие с пользователем и тестирование.
- Встроенная диагностика: C++-тесты ядра и интеграционные Python-тесты.
- Механизм передачи детализированных ошибок из C++ в Python через `last_error` (начиная с v4.1).
- Поддержка моделирования системы компьютерного зрения (классы cam, locim, loctr, иерархия событий).

Система может служить основой для масштабной WMS с возможностью добавления GUI, сетевого взаимодействия, интеграции с промышленными контроллерами и БД.
